# Cursor 会话清理

在本机查看 Cursor 对话，并按条删除。程序只读写你电脑上的数据库，不会上传。

## 环境

需要 Linux 上的 Python 3.11、GTK 4 和 libadwaita。Fedora 上对应这些包：

- `python3`
- `python3-gobject`
- `gtk4`
- `libadwaita`

## 启动

在应用列表里打开「Cursor 会话」。图标是蓝色底、带删除标记的列表。

在仓库根目录执行：

```bash
bin/cursor-chat-desk
```

窗口打开后可以先浏览。删除和恢复之前，要完全退出 Cursor。主进程还在时，删除按钮会停用。从系统终端启动，不要从 Cursor 里的终端启动，否则退出 Cursor 时窗口会被关掉。

## 界面

左侧是会话列表，按最近更新排序。可以用标题、项目或编号筛选，也可以只看未归档或已归档。右侧是正文预览。按住 Ctrl 可以多选，按 Delete 会打开删除确认。

子会话默认不显示。删除父会话时，仍会把它的子会话一起删掉，确认框里会写明条数。

## 删除时会动哪些数据

确认之后，程序先把相关行复制到 `~/.local/share/cursor-chat-desk/backups/`。然后删除这些内容：

- 全局库 `composerHeaders` 里的会话行
- 该会话的消息、检查点、草稿和会话内文件快照
- 工作区库里同一编号的副本
- `conversation-search.db` 里的本地搜索记录
- `~/.cursor/projects/*/agent-transcripts/<会话编号>/`
- `~/.cursor/chats/*/<会话编号>/`

转录目录是移进备份，不是直接抹掉。符号链接会跳过。

这些内容会保留：

- `agentKv` 里按哈希存放的大块数据
- 编辑器设置、账号和密钥项
- 整份 `state.vscdb` 文件

删完会话后，数据库文件不一定马上变小。重新打开 Cursor，在命令面板运行 Developer: GC Agent KV Blobs，才能回收那些哈希块。

## 恢复

点「恢复上次删除」，会把最近一次备份写回原库，并把转录目录移回去。Cursor 正在运行时不能恢复。已有的同名目录不会被覆盖。

## 限制

Cursor 的库格式没有公开文档，升级后可能对不上。对不上时，删除会直接停下来，不会改库。

编号里只接受小写字母、数字和连字符。读到不符合的编号时，列表里不显示，删除也会拒绝。
